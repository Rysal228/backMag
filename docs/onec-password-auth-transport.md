# Новый парольный вход: клиент Django для защищённого сервиса 1С

**Этап подготовительный.** Код `OneCPasswordAuthClient` не подключён к
`AuthService.login`, регистрации, refresh или маршрутам Angular. Не вводите новые
пароли пользователей до создания защищённого endpoint в 1С.

## Контракт внутренней проверки

Будущий, пока НЕ опубликованный endpoint должен принимать только POST:

```http
POST https://<проверяемое_имя_сервера>/ServiceCarAuth/hs/auth/password/verify
Authorization: Basic <technical-service-credentials>
Content-Type: application/json

{"phone":"7XXXXXXXXXX","password":"<user input>"}
```

При совпадении пароля 1С выдаёт:
```json
{"authenticated":true,"onecId":"<native-1c-uuid>","phone":"7XXXXXXXXXX",
"isActive":true,"roles":["user"]}
```

Для отсутствующего пользователя, MAX-only аккаунта без пароля или неверного пароля:
```json
{"authenticated":false}
```
без раскрытия причины и существования записи.

Ответы об ошибке сервиса (в частности 401 Basic) не должны трактоваться как неверный пароль пользователя. 1С не отправляет Django хеши. Django не хранит хеши.

## Строгие требования безопасности

Служебная публикация 1С: HTTPS **с проверкой сертификата**, выделенный технический пользователь с ограниченными правами, закрытый от внешних пользователей auth URL, отсутствие логирования паролей, rate limit по IP и учётной записи. Для внутренних запросов нельзя полагаться только на сетевой адрес.

Публичный Django endpoint не менять до полного end-to-end теста и обратной совместимости JWT. Создание аккаунтов, смена пароля, сброс пароля и привязка MAX — отдельные операции с собственными проверками полномочий. Нельзя позволять сменить пароль по одному UUID.

Настройки для последующей активации клиента (пока не устанавливайте их):
- `ONEC_AUTH_VERIFY_URL`: полный HTTPS URL, содержащий путь к **отдельному защищённому** сервису 1С.
- `ONEC_AUTH_API_USER`: техническая учётная запись 1С.
- `ONEC_AUTH_API_PASSWORD`: её технический пароль (только секретное хранилище/.env, не GitHub).

Это адрес/учётные данные интеграции, **не feature flags**. Без этих настроек клиент не отправит пароль — будет ошибка 503. Запрещены HTTP и неполные credentials. Существующий `ONEC_ALLOW_UNAUTHENTICATED_INTERNAL=1` **не применяется** к этому клиенту.

## Тесты

```bash
docker compose exec backend python manage.py test users.tests.test_onec_password_auth_security -v 2
```

Тесты используют mock HTTP и не проверяют реальный TLS/1C. Для первого реального входа нужна специальная тестовая учётная запись без настоящих пользовательских паролей. Ни вводить пароли в shell history, ни передавать их в ChatGPT нельзя.

## Зависимости

1. Регистры и внутренние функции 1С: подготовлены в отдельном PR; требуется сборка/проверка Конфигуратора 8.5.1.1522.
2. Администрирование криптографии: PBKDF2-HMAC-SHA256 вместо SHA1, проверка реального типа хеша на тестовом пользователе.
3. Отдельный технически аутентифицированный TLS HTTP сервис 1С, тест запрета неаутентифицированного вызова.
4. Ограничение частоты попыток, отсутствие журналирования и тест защиты от перебора.
5. После этих шагов подключать к `AuthService.login` в одном контролируемом выпуске совместно с регистрацией и refresh. **MAX в этот этап не включать.**

См. OWASP: https://cheatsheetseries.owasp.org/cheatsheets/Web_Service_Security_Cheat_Sheet.html
