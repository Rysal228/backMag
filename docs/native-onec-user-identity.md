# Переход на нативный UUID 1С

**Источник идентичности:** UUID ссылки элемента
`Справочник.ПользователиПриложения` (поле `onecId`).
Django больше не создаёт второй UUID для приложения.

## Изменения в API

- При `POST /user` 1С сама создаёт UUID, возвращает `user.onecId`.
- `POST /max/resolve` использует подтверждённый MAX ID, телефон и,
  при первом создании, имя/фамилию; второй UUID не нужен.
- `POST /password/setup` сверяет только телефон + `onecId`
  и наличие пароля в регистре.
- В `GET /users/mechanics` поле `id` равно UUID 1С.
- Ответ `GET /users/profile/` сохраняет прежнюю структуру с полем `id`,
  но это теперь UUID 1С.
- JWT `user_id` должен содержать тот же UUID 1С.

## Переходное ограничение текущего PR

Пока автомобили, заказы и чаты всё ещё имеют ForeignKey к Django
`CustomUser`, создаётся только временная локальная ORM-строка
**с первичным ключом ровно `onecId`**. Она не хранит действующий пароль.
Все новые роли актуализируются из 1С перед выдачей/проверкой токенов.
Это не конечный отказ от модели `CustomUser`; для него нужны отдельные
изменения моделей автомобилей, заказов, чатов, WebSocket и миграций.

Старые локальные записи с UUID, отличным от UUID в 1С, **не
перепривязываются молча**. При совпадающем телефоне и другом UUID
бэкенд возвращает конфликт. Раз пользователь разрешил потерю учебных
данных, перед совместным переключением следует очистить тестовую
PostgreSQL, не теряя служебные справочники и настройки.

Не применять PR Django отдельно от
`Rysal228/1c#18`, в котором удалён реквизит второго идентификатора
и изменён контракт 1С.

## Проверки до объединения

- Новый пользователь, созданный только в 1С, входит по паролю.
- Регистрация через сайт возвращает JWT с `user_id = onecId`.
- Новый MAX пользователь привязывается по проверенному телефону.
- Вход через MAX-код, обновление токенов и смена роли работают.
- При снятии роли или выключении `Активен` в 1С сессия больше
  не авторизует действия.
- Административная смена и первая установка пароля работают.
- Список специалистов отдаёт UUID из 1С.
- Автомобили, заказы и чаты пока требуют переходный ORM-слой.

**Нельзя удалять PostgreSQL сейчас.** Это делается только при
переключении схемы и зависимых моделей.
