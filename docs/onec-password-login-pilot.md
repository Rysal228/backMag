# Вход через 1С — ServiceCarAPI

## Что работает

При парольном входе фронтенд вызывает существующий Django endpoint.
Django передаёт телефон и пароль в существующий метод 1С
`POST /ServiceCar/hs/api/password/verify`. 1С возвращает
`authenticated: true/false`, а при успехе — `onecId`, телефон,
активность и роли. Django сопоставляет этот идентификатор с
`CustomUser.onec_id` и выдаёт JWT старого формата.

Вход через Django-пароли отключён в `AuthService.login`; MAX не меняется.

## Настройки

Точный адрес уже задан по умолчанию в Python:

```text
http://host.docker.internal:8081/ServiceCar/hs/api/password/verify
```

Поэтому дополнительные флаги для включения этого метода **не нужны**.
`ONEC_AUTH_VERIFY_URL` можно оставить незаданным. Если там уже
настроен другой URL, он имеет приоритет — проверьте значение
перед запуском. `ONEC_AUTH_API_USER` и `ONEC_AUTH_API_PASSWORD`
для существующего внутреннего HTTP-маршрута должны быть незаданными.

**Ограничение:** текущий обмен Django–1С осуществляется по
незашифрованному HTTP. Пароль передаётся внутри запроса в открытом
виде. Не открывайте внутренний порт 8081 наружу и не используйте
непроверенные адреса для передачи паролей.

## Проверка после сборки

В запущенном Django-контейнере:

```bash
python manage.py test users.tests.test_onec_password_auth_security users.tests.test_onec_password_login_pilot -v 2
```

Проверить вход через обычную форму фронтенда с уже установленным
в 1С паролем, затем отказ с неверным паролем и отдельно MAX.
Не публиковать реальные пароли в логах и переписке.

## Ещё не перенесено

Регистрация новых аккаунтов пока записывает пароль **только в
Django**. У новых аккаунтов не появится пароль в 1С и повторный вход
не будет работать. До переноса регистрации этот маршрут нельзя
считать завершённой миграцией всей системы. Смена паролей через
Django пока отключена, поскольку пароль должен меняться в 1С.

Проверка `onec_id` и ролей обязательна, так как старый Django
`CustomUser.id` остаётся в JWT и связях с заказами, автомобилями и чатами.
